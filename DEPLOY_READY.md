# DEPLOY_READY.md — C3 Hays website

The site has **two production targets that coexist**, selected by env vars. Neither
breaks the other; the switch lives in `next.config.ts` (`output: cmsLive ? undefined : "export"`).

| Target | When | Output | Host | Content source |
|---|---|---|---|---|
| **Static export** | `CMS_LIVE` unset (default) | `out/` (static HTML) | **GitHub Pages** (unchanged) | hand-built pages (`src/components/home/*`, `src/data/*`) |
| **Live SSR** | `CMS_LIVE=1` + `NEXT_PUBLIC_CMS_URL` | `.next/` (server runtime) | **Vercel** | live from C3 Studio `/api/content` |

Canonical production domain: **c3hays.com** · CMS: **studio.c3hays.com**.

## Environment variables (`.env.example`)

| Var | Purpose | Prod value | Local value |
|---|---|---|---|
| `NEXT_PUBLIC_CMS_URL` | C3 Studio content API base. Unset → CMS calls return null (static fallback). | `https://studio.c3hays.com` | `http://localhost:4544` |
| `CMS_LIVE` | `1` → server runtime / SSR (`output: undefined`). Unset → static export. | `1` (Vercel) | `1` to test SSR |
| `NEXT_PUBLIC_BASE_PATH` | Sub-path prefix. **GitHub Pages only.** | _(unset)_ | _(unset)_ |

`.env.example` is committed (it holds no secrets); `.env*.local` stays gitignored.

### 2. Live SSR — Vercel (real-time CMS)
```bash
CMS_LIVE=1 NEXT_PUBLIC_CMS_URL=https://studio.c3hays.com npm run build
# local test against the running Studio:
CMS_LIVE=1 NEXT_PUBLIC_CMS_URL=http://localhost:4544 npm run build
```
Evidence:
```
✓ Compiled successfully
✓ Generating static pages using 13 workers (15/15)
Route (app)
┌ ƒ /                  ← Dynamic (server-rendered on demand)

```
The homepage flips to `ƒ (Dynamic)` because its live CMS fetch uses `cache: "no-store"`,
so every request server-renders fresh content from C3 Studio. No `output: export`, so dynamic
rendering is allowed — build is clean.

## How the Vercel deploy works

`vercel.json` pins this project to the SSR path:
- `framework: nextjs`, `buildCommand: next build`
- `build.env` + `env` set `CMS_LIVE=1` and `NEXT_PUBLIC_CMS_URL=https://studio.c3hays.com`

So a Vercel deploy automatically builds in server-runtime mode and serves `c3hays.com` live
from `studio.c3hays.com`. Staff edit + Publish in C3 Studio → the next request to the site
reflects it (real back-and-forth). Point the `c3hays.com` domain at the Vercel project; keep
`studio.c3hays.com` pointed at the C3 Studio deployment.

> Override the Studio URL per-environment in the Vercel dashboard if you run a staging Studio.
> `NEXT_PUBLIC_BASE_PATH` must stay **unset** on Vercel (served at the domain root).

## What stays on GitHub Pages

`.github/workflows/deploy.yml` is **unchanged**: on push to `main` it runs the default
`npm run build` (no `CMS_LIVE`) → static export → GitHub Pages at `/c3hays-redesign/`. This
remains a fully working fallback / archive target. The two targets share one codebase and one
`next.config.ts`; only env vars differ.

## CMS live-path sanity check

- C3 Studio is serving on `:4544`: `GET /api/content` → 200, `GET /api/content/sermons` → 200.
- `GET /api/content/screen/%2F` (slug `/`) returns the home screen with **7 visible blocks**,
  first block `component_type: "hero"`.
- Code path (`src/app/page.tsx`): `await getCMSScreen("/")` → if `blocks.length`, renders the
  **"Live from C3 Studio"** banner + `<CMSBlocks>` (plus `getCMSSermons/Events/Locations`);
  otherwise falls back to the hand-built `<Hero/> … <GiveSection/>`.
- `src/lib/cms.ts`: `cmsFetch` short-circuits to `null` when `NEXT_PUBLIC_CMS_URL` is empty
  (export-safe), and uses `cache: "no-store"` + a 2.5 s timeout when configured (live, fail-soft).

Confirmed: with `NEXT_PUBLIC_CMS_URL` set and the SSR build, the homepage is dynamic and pulls
the live 7-block bundle from C3 Studio.
